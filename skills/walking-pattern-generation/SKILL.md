# 歩行パターン生成

共通の品質契約、長時間処理、出力、Git規則は対象リポジトリの`AGENTS.md`に従う。

## 作業手順

1. 移植元、対象API、既存差分、関連Issue、既知の欠陥を確認する。
2. 状態、入力、出力、単位、座標frame、軸、符号、周期、初期・終端条件を整理する。
3. 数式、離散化、状態更新順、支持脚切替、失敗条件を実装前に確定する。
4. 純粋な計算コアを通信、シミュレーション、保存、描画から分離する。
5. 代表入力、不変条件、移植元との数値回帰で意味と互換性を検証する。

## 参照資料

- 数式、離散化、収束、許容差を扱う場合は[numerics.md](references/numerics.md)を読む。
- ROS 2/C++からの移植やAPI互換性を扱う場合は[migration.md](references/migration.md)を読む。
- テスト範囲と合格条件を決める場合は[validation.md](references/validation.md)を読む。

## 常に守る条件

- 単位、座標frame、軸、符号、配列順序、サンプル時刻を公開境界で明示する。
- 制御目標、推定状態、シミュレーション状態を区別する。
- 浮動小数点時刻を反復加算せず、可能ならサンプル番号から算出する。
- 移植元の欠陥を修正する変更と互換性移植を混在させない。
- 単に転倒しないことを歩行制御の合格条件にしない。
