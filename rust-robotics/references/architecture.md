# Rustアーキテクチャ

処理を次の順で読める形にする。

```text
入力値 -> 検証 -> 正規化・計算 -> 出力値 -> 通信・シミュレーション・保存・描画
```

- 時間発展の状態を小さな値型にまとめ、状態遷移の意味を明確にする。
- `main.rs`は入力準備、ライブラリ呼び出し、副作用実行だけの薄い層にする。
- 計算、シミュレーション、通信、ロギングは依存方向を保てる単位に分ける。
- 複数クレートはCargo workspaceで管理し、ルートの`Cargo.lock`を使う。
- 可変状態やiterator記法を目的化せず、数式と状態遷移の読みやすさを優先する。
- doc commentには逐語訳でなく、単位、frame、配列要素、前提、失敗条件を書く。
